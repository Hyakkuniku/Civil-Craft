# Submitted assessment answer review

Run `dotnet run --project Tests/QuizAssessmentReview/QuizAssessmentReview.csproj` from the Unity project root.

The harness directly compiles production `QuizView`, `QuizResultCard`, `QuizChoiceView`, `QuizData`, `QuizProgressSaveData`, and `QuizProgressUtility`. It checks all combinations of authored/reversed question and choice orders at variable counts, real card button events mapping displayed choices to original source indices, matching visible highlights/letters (including beyond Z), source-based green/red grading, correction visibility, image/caption preservation, null/legacy selections, plain text, explanation copy, card sizing, cleanup, result-only controls, and unchanged practice flow. Both prompt and result rendering map through saved stable question IDs and choice permutations; selected/correct result letters match their original display positions while content and correctness retain their source identities. Busy/save-error/correct-practice states block remapped choice events; wrong practice feedback preserves retry mapping. Measurement includes TMP margins and verifies font-relative gutters contain the authored Bekind capital-glyph overshoot. Source guards check the manager's post-save submission/resume/order handoff and the real layout's scrollable one-column path.

Unity hierarchy/input/instantiation and TMP measurement are small boundary doubles; actual font rendering, camera composition, touch scrolling and scene input remain native Unity/device checks. The suite never accesses live accounts, saves, scenes, rewards, or network.
